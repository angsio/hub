A scheduling board for tasks, events, and reminders, with a language-model
agent that can read the board and add to it on request.

## What it does

Items are grouped under themes — Work, Personal, whatever you create — and shown
either as a board or on a weekly timetable. The agent sits alongside it: ask it
what is due this week and it reads the board; ask it to schedule something and it
proposes the change and waits for confirmation before writing.

## How it is built

The client is React with react-router. The API is Express, and data lives in
MongoDB through Mongoose.

Tasks, events, and reminders share one collection using Mongoose
**discriminators**. They have a common base — title, theme, timestamps — and then
each type adds its own fields: a deadline for tasks, a start and end for events,
a single time for reminders. One collection, three shapes, no duplicated schema.

## The agent

The interesting part is how the agent chooses its tools.

Rather than showing the model every tool on every request, each tool's
description is converted into an **embedding** — a list of numbers representing
its meaning — and stored in Supabase. When a message arrives, the message is
embedded too, and only the closest-matching tools are sent along. The idea is
that adding a tenth tool should not degrade how well the model picks among the
first nine.

Tools that only read data run immediately. Tools that write are marked
`confirm: true`, which stops the loop and returns the proposed action to the
client for approval before anything reaches the database.
